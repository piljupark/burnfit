## 고치면 좋음

### 비용 · 속도

- 트레이너 식단 피드가 회원마다 따로 읽는다 (`lib/services/meal_feed_service.dart:50` 회원당 피드백 300개) → 회원 수만큼 읽기가 늘어난다. 식단 탭을 오갈 때마다 다시 읽는다. → 날짜 범위로 묶어 읽기 · 탭 전환 때 다시 읽지 않기 · 피드백 수를 식단 문서에 모아 두기.
- 보낸 피드백 화면은 회원 기준 최근 피드백 100개를 읽어 내 것만 거른다 (`trainer_sent_feedback_screen.dart`). 담당이 여러 번 바뀐 회원은 내 것이 덜 보일 수 있다 → 필요하면 `trainerId` 조건 + 색인을 더한다 (색인 배포 필요).
- 지난 운동 불러오기(`getPreviousWorkouts`)와 관리자 목록(회원·트레이너·탈퇴)에 개수 제한이 없다 → 페이지로 나눠 읽기.
- 관리자 대시보드가 매번 기록을 다 세서 계산 → 서버에서 미리 모아 두기.

### 데이터 · 규칙

- 시각을 기기 시계로 저장하는 곳이 있다 → `FieldValue.serverTimestamp()`.
- `memberName`·`trainerName`·`imageUrls` 같은 값을 규칙에서 검사하지 않는다, 글자 길이·저장 빈도 제한 없음 → `firestore.rules` 에 길이·형식 검사.
- 트레이너가 다른 트레이너의 이메일·생년월일을 읽을 수 있다 → 공개용 필드만 따로 두거나 규칙 좁히기.
- 식단 사진 주소가 다운로드 토큰 주소라 주소만 알면 누구나 본다 → 규칙으로 읽는 경로를 쓰거나, 최소한 주소를 밖으로 내보내지 않기.
- 식단·계정을 지워도 Storage 사진이 남는 경우 → 삭제 함수에서 함께 지우기.
- 로그아웃해도 기기 캐시와 운동 임시저장이 남는다 (`lib/main.dart:67` 캐시 무제한, `clearPersistence` 없음) → 로그아웃 때 정리 (한 기기를 여럿이 쓰는 센터 기기 대비).

## 개인정보 항목을 늘릴 때 (예: 휴대폰 번호 · 엑셀 명단)

2026-10-13 검토. 휴대폰 번호로 엑셀 명단과 가입 계정을 잇는 기능을 만들 때 지킬 것.

- **사용자 문서(`users/{uid}`)에 넣지 않는다.** 이 문서는 같은 센터 트레이너도 읽을 수 있어(담당 회원 · 다른 트레이너) 번호가 트레이너끼리도 보이게 된다. 파이어베이스는 칸별 읽기 권한이 없다.
  → 신체 정보(`users/{uid}/body_profile`)처럼 `users/{uid}/contact` 같은 별도 문서에 두고, 본인 · 그 센터 관리자만 읽게 한다. 화면은 '010-****-5678', 관리자가 눌러야 전체.
- 엑셀 명단은 센터 관리자만 읽고 쓰는 모음에 둔다. 필요한 칸만(이름 · 번호 · 구분 · 담당 · PT 정보). 가입 · 연결된 줄은 지우고, 오래 가입하지 않는 줄은 정리.
  → 2026-10-13 반영: `centers/{centerId}/roster/{번호 숫자}` (규칙 `hasValidRosterRow`, 테스트 `test/rules/roster.test.js`). 승인하며 담당 · PT를 붙이면 줄을 지운다. 오래된 미가입 줄은 아직 자동으로 지우지 않는다 — 관리자가 '회원 명단'에서 'M월 d일 올림'을 보고 지운다 (필요하면 서버 정리 함수).
- 처리방침에 '센터가 등록한 명단 보관 · 처리', '휴대폰 번호' 추가.
- 탈퇴 함수(`account_deletion.js`)가 연락처 문서 · 명단 줄도 지우게.
  → 연락처는 사용자 문서와 함께 지워진다(`recursiveDelete`). 명단 줄은 계정과 이어 두지 않고 승인 때 지우므로 탈퇴 함수는 고치지 않았다.
- 번호만으로 자동 승인하지 않는다 (문자 인증이 없으면 남의 번호로 가입 가능) → 관리자 가입 승인 화면에 '명단과 일치'만 표시. 문자 인증을 붙이면 자동 승인 검토.
- 확인함: 개발용 기록(`AppLogger.debug`)은 개발 빌드에서만 찍혀 출시 앱에는 남지 않는다. 전송 · 저장 암호화는 파이어베이스 기본. App Check는 위 '꼭' 항목.
